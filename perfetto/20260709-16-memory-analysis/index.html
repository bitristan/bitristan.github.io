HeapGraphTracker：C++ 导入器

Section titled “HeapGraphTracker：C++ 导入器”

HeapGraphTracker（importers/proto/heap_graph_tracker.h）处理 ART 堆图 protobuf 包。关键设计：

基于序列的状态管理：每个 seq_id 维护独立的 SequenceState，包含 interned 类型/字段/位置名、object_id 到 DB 行的映射、延迟大小对象的映射。这处理了堆图数据可能乱序到达的情况。

延迟大小填充：大多数对象在自己的消息中不携带 self_size——大小信息在类消息处理后才可用。deferred_size_objects_for_type_ 记录需要回填的对象，在 FinalizeProfile() 中统一处理。

Native 大小计算：PopulateNativeSize() 遍历图，追踪 libcore.util.NativeAllocationRegistry 对象的 cleanerThunk.this0 → nativeSize → cleaner.next 链，将 native 内存归因到持有 NativeAllocationRegistry 的 Java 对象。

GC 可达性

Section titled “GC 可达性”

每个 heap_graph_object 有 reachable 标志——由 ART 的 GC 标记阶段设置。root_type 记录了对象的 GC root 类型（如 GLOBAL_ROOT、LOCAL_ROOT、THREAD_ROOT 等）。root_distance 是从 GC root 到该对象的最短路径长度。

对象树与类摘要

Section titled “对象树与类摘要”

object_tree.sql 沿最短路径树聚合累积大小，支持交互式的堆探索——“这个对象引用了什么？什么引用了它？”

class_summary_tree.sql 按类名聚合，生成类似火焰图的表示：

  • self_count / self_size：该类的实例直接占用
  • cumulative_count / cumulative_size：包括被引用对象的累积占用

路径分析

Section titled “路径分析”

HeapGraphTracker::FindPathFromRoot() 执行 DFS（深度优先搜索，用 std::vector 模拟栈避免递归溢出），找到从 GC root 到目标对象的路径。结果是一个 (depth, parent) 序列，可以重建完整的引用链。

数据源

Section titled “数据源”

DMA-BUF 是 Linux 内核的跨设备共享缓冲区机制。GPU 分配的内存、camera buffer、显示 buffer 都通过 DMA-BUF 管理。

LMK 事件分析

Section titled “LMK 事件分析”

android/memory/lmk.sql 统一了三代 LMK（Low Memory Killer）事件格式：

时期格式
2025+instant track lowmemorykiller，lmk,<pid>,<kill_reason_raw>,<oom_score_adj>，dur = 0
2021+slice-based lmk,<pid>,<kill_reason_raw>,<oom_score_adj>，dur > 0
旧版counter-based kill_one_process

两种现代格式使用相同的 str_split 解析逻辑，仅通过 dur = 0（instant）vs dur > 0（slice）区分。kill_reason_raw 是原始枚举值，通过 _android_lmk_kill_reason_string() 转换为可读字符串。Kill 原因包括：PRESSURE_AFTER_KILL、LOW_SWAP_AND_THRASHING、LOW_MEM_AND_SWAP、DIRECT_RECL_STUCK 等 10+ 种。

本文小结

Section titled “本文小结”

Perfetto 的内存分析覆盖了 Java 堆、native 堆和内核内存三个层次。Java 堆分析通过支配树、类摘要和路径分析支持从宏观到微观的逐层深入。Native 堆剖析通过调用栈归因定位内存分配热点。DMA-BUF 追踪通过 binder flow 实现跨进程的 GPU 内存归因。进程级内存分析将 RSS、swap、OOM adj 和 LMK 事件关联，提供完整的内存压力视图。这些分析全部通过 PerfettoSQL 模块化实现，可以自由组合。
