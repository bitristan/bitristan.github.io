Perfetto （十）：Tracing SDK

SDK 的定位

Section titled “SDK 的定位”

Perfetto Tracing SDK 是一个可嵌入的 C++ 库，让应用程序通过 TRACE_EVENT 宏发射自定义 trace 事件。它不是独立的工具——它是 Perfetto 三方模型中 Producer 的用户态实现，将应用代码与共享内存缓冲区、ProtoZero 序列化、IPC 层连接起来。

公共 API 层

Section titled “公共 API 层”

SDK 的公共头文件位于 include/perfetto/tracing/，核心入口：

Tracing 初始化：perfetto::Tracing::Initialize(TracingInitArgs) —— 全局一次性调用。

TracingSession：perfetto::Tracing::NewTrace(BackendType) —— 创建追踪会话，返回 std::unique_ptr<TracingSession>。

TrackEvent 宏：TRACE_EVENT、TRACE_EVENT_BEGIN、TRACE_EVENT_END、TRACE_EVENT_INSTANT、TRACE_COUNTER。

自定义数据源：DataSource<T> 模板基类——用于创建非 TrackEvent 的自定义数据源。

Track 模型：ThreadTrack、ProcessTrack、CounterTrack、CustomTrack——类型化的 track 层次结构。

三种后端模式

Section titled “三种后端模式”

SDK 支持三种追踪后端，通过 TracingInitArgs.backends 指定：

后端常量说明
系统 tracedkSystemBackend连接到 traced 守护进程。Android/Linux 生产环境的标准模式。
进程内kInProcessBackendTracingService 运行在同一进程内。无需 traced 守护进程，无需 IPC。
自定义kCustomBackend用户提供自己的 TracingBackend 实现，用于自定义 IPC 通道。

Tracing::Initialize() 声明为 PERFETTO_ALWAYS_INLINE。这使得编译器可以做死代码消除：如果调用者从未传入 kInProcessBackend，整个 InProcessTracingBackend 代码（约 200 KB）会被链接器 GC 掉。

进程内模式

Section titled “进程内模式”

当使用 kInProcessBackend 时：

  1. InProcessTracingBackend 懒创建 TracingService 实例。
  2. 使用 InProcessSharedMemory::Factory 创建堆分配的共享内存（不需要 OS 共享内存）。
  3. 整个追踪服务、Producer、Consumer 运行在同一进程内。没有 IPC，没有守护进程。
  4. trace 数据通过 ReadTrace() 读出，或通过 fd 写入文件。

Tracing 初始化

Section titled “Tracing 初始化”

Tracing::Initialize() 的内部流程：

  1. 验证构建配置（dcheck_is_on_ 等）。
  2. 配置时钟（CLOCK_MONOTONIC 或 CLOCK_MONOTONIC_RAW）。
  3. 创建 TracingMuxerImpl 单例——在专用的 “TracingMuxer” 线程上运行。
  4. 实例化请求的后端（in-process、system、custom）。
  5. 初始化 TrackRegistry。

允许多次调用 Initialize()（添加额外后端），但只有第一次调用设置全局参数。

类别系统

Section titled “类别系统”

静态类别

Section titled “静态类别”

静态类别在编译时注册：

展开后：

  1. 创建 constexpr Category kCategories[] 数组。
  2. 创建 constexpr TrackEventCategoryRegistry 用于编译时查找。
  3. 声明 std::atomic<uint8_t> g_category_state_storage[]——每个类别一个原子字节，每个 bit 对应一个数据源实例（最多 8 个并发实例）。

类别索引在编译时通过 constexpr 的 TrackEventCategoryRegistry::Find() 解析。如果类别未注册，编译失败。

动态类别

Section titled “动态类别”

动态类别使用 DynamicCategory（字符串包装），绕过编译时检查。运行时通过 unordered_map<string, bool> 缓存评估结果。首次遇到时获取数据源锁并评估配置。

类别组

Section titled “类别组”

Category::Group("cat1,cat2") 支持逗号分隔的类别组，在单个 Category 对象中存储最多 4 个名称。

TLS 架构

Section titled “TLS 架构”

SDK 的线程安全模型基于每线程全局 TLS 对象：

TracingTLS（每线程一个）：

  • generation：与 TracingMuxerImpl::generation_ 比较，检测过期的 trace writer。
  • is_in_trace_point：重入保护标志。
  • data_sources_tls[]：每种数据源类型的 TLS。

DataSourceThreadLocalState（每种数据源每线程一个）：

  • per_instance[]：每个数据源实例的 TLS。

DataSourceInstanceThreadLocalState（每个实例每线程一个）：

  • trace_writer：关键对象——每线程每实例一个 TraceWriter。
  • incremental_state：类型擦除的 interning 表。
  • data_source_custom_tls：自定义 TLS（如 TrackEventTlsState）。

TraceWriter 的按需创建

Section titled “TraceWriter 的按需创建”

TraceWriter 不是预分配的——它在第一次 trace point 触发时懒创建：

  1. DataSourceType::FirstActiveInstance() 检查 tls_inst->trace_writer 是否为 null。
  2. 如果为 null，调用 PopulateTlsInst()：
    • 从全局 DataSourceState 复制 backend_id、buffer_id 等。
    • 调用 TracingMuxerImpl::CreateTraceWriter()——通过 SharedMemoryArbiter 分配写入 SMB 的 writer。
    • 创建增量状态和自定义 TLS。
  3. 创建后的 TraceWriter* 缓存在 TLS 中，后续 trace point 直接复用。

重入保护

Section titled “重入保护”

ScopedReentrancyAnnotator 在 trace point 期间设置 is_in_trace_point = true。如果追踪代码本身触发了新的 trace 事件（例如追踪内存分配函数），TracePrologue() 检测到重入标志后直接返回，避免无限递归。

基于 Generation 的清理

Section titled “基于 Generation 的清理”

当追踪会话停止时，TracingMuxerImpl::generation_ 递增。每个线程在下一次 trace point 时检测到 generation 不匹配，调用 DestroyStoppedTraceWritersForCurrentThread() 清理过期的 TraceWriter。

TracingSession：Consumer API

Section titled “TracingSession：Consumer API”

TracingSession 的操作都是异步的——Setup()、Start()、Stop() 立即返回，结果通过回调通知。*Blocking() 变体封装了同步等待。

Amalgamation：嵌入式打包

Section titled “Amalgamation：嵌入式打包”

SDK 通过 tools/gen_amalgamated 工具打包为单文件：

  • perfetto.h：包含所有公共头文件。
  • perfetto.cc：包含所有实现源码。

作为静态库链接。关键构建参数：is_perfetto_embedder=true、perfetto_amalgamated_sdk=true。

使用 amalgamated SDK 时：#include <perfetto.h> 即可，不需要 Perfetto 的源码树。

本文小结

Section titled “本文小结”

Perfetto Tracing SDK 是一个精心设计的嵌入式追踪库。编译时的 constexpr 类别注册将 enable 检查压缩为单次原子加载。每线程的 TLS 架构避免了写入时的锁竞争。按需创建的 TraceWriter 在不活跃的线程上不消耗资源。inline 的 Initialize() 调用允许链接器消除未使用的后端代码。进程内模式让最简单的使用场景零外部依赖。这些设计使得 SDK 可以嵌入到从 Android 系统服务到独立 CLI 工具的各种场景中。
