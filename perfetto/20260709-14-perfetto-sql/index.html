Perfetto （十四）：PerfettoSQL 与标准库

PerfettoSQL 的定位

Section titled “PerfettoSQL 的定位”

PerfettoSQL 是 SQLite 的超集，专门为 trace 分析设计。它不是一门新语言——它在 SQLite 的 LALR 语法上精确扩展了 7 种新语句类型（加上 1 种标准 SQL 透传标记），使得模块化、类型安全、高性能的 trace 分析成为可能。

语法扩展：7 种新语句 + 1 种透传

Section titled “语法扩展：7 种新语句 + 1 种透传”

1. INCLUDE PERFETTO MODULE

Section titled “1. INCLUDE PERFETTO MODULE”

从标准库或用户注册的包中导入 SQL 模块。模块路径用点分隔（如 sched.runnable），对应文件系统中的 sched/runnable.sql。

执行时，模块的 SQL 被推入执行栈的一个新帧中，在当前语句之前执行完毕。如果模块已经被导入过，跳过（include-once 语义）。如果模块导入失败，错误被记录到”中毒”集合中——后续的 INCLUDE 同一模块会重放相同的错误。

2. CREATE PERFETTO TABLE

Section titled “2. CREATE PERFETTO TABLE”

创建由 Dataframe 支撑的物化表。与普通 CREATE TABLE 的区别：Perfetto 表的列有类型化的排序状态和空值信息，可以参与 Dataframe 的查询优化。

可选的 USING 子句指定底层实现（如 USING dataframe）。

3. CREATE PERFETTO FUNCTION

Section titled “3. CREATE PERFETTO FUNCTION”

定义 SQL 函数。参数用 $name 引用。返回类型可以是标量（RETURNS INT）或表（RETURNS TABLE(...)）。

CREATE PERFETTO FUNCTION 有一个重要变体——DELEGATES TO：

DELEGATES TO 将函数实现委托给 C++ 注册的 __intrinsic_* 函数。参数类型中的 JOINID(slice.id) 注解关联到表的列，支持类型检查和查询优化。

4. CREATE PERFETTO VIEW

Section titled “4. CREATE PERFETTO VIEW”

创建 PerfettoSQL 视图。与普通 CREATE VIEW 的区别：Perfetto 视图可以引用 PerfettoSQL 函数和宏，支持参数化（通过 $name 绑定）。

5. CREATE PERFETTO MACRO

Section titled “5. CREATE PERFETTO MACRO”

参数化的 SQL 片段。宏在编译期做文本替换——$intervals 被替换为调用者传入的实际表达式。这使得宏可以接受表名、子查询等作为参数，而普通函数做不到。

宏的 RETURNS 类型指定了替换后的语法类别：TableOrSubquery（出现在 FROM 子句中）、Expr（出现在表达式中）、UnparenExprList（逗号分隔的表达式列表）等。

6-8. CREATE/DROP PERFETTO INDEX

Section titled “6-8. CREATE/DROP PERFETTO INDEX”

在物化表上创建索引，加速后续查询。

解析器架构

Section titled “解析器架构”

Lemon 语法

Section titled “Lemon 语法”

PerfettoSQL 的语法定义在 src/trace_processor/perfetto_sql/syntaqlite/perfetto.y——一个 Lemon（LALR）解析器生成器文件。关键设计：扩展关键字被声明为 %fallback ID——如果它们不在 PerfettoSQL 特有的上下文中出现，就退化为普通标识符，保持对标准 SQL 的向后兼容。

PerfettoSqlParser

Section titled “PerfettoSqlParser”

C++ 层的 PerfettoSqlParser（parser/perfetto_sql_parser.h）是一个迭代式解析器：

Statement 是一个 std::variant，包含 8 种类型：7 种 PerfettoSQL 语句 + SqliteSql（标准 SQL 透传标记）。每种语句类型捕获足够的信息用于执行——CreateTable 包含列定义和 SQL body 的字节偏移范围。

内置宏展开器

Section titled “内置宏展开器”

在查找用户定义的宏之前，解析器先检查内置的 __intrinsic_* 宏：

宏作用
__intrinsic_stringify!将标识符转换为字符串字面量
__intrinsic_token_apply!对逗号分隔列表的每个元素应用宏
__intrinsic_token_apply_prefix!带前缀的列表应用
__intrinsic_token_apply_and!用 AND 链接列表元素
__intrinsic_token_apply_and_prefix!带前缀的 AND 链接

这些是 PerfettoSQL 的元编程原语。它们操作原始 token 文本，使得宏可以处理可变数量的参数——例如 _interval_intersect 宏可以接受 2 到 15 个输入表。

Section titled “栈式执行”

PerfettoSqlConnection 使用栈式（非递归）执行模型：

__intrinsic_table_ptr 桥接模式

Section titled “__intrinsic_table_ptr 桥接模式”

C++ 函数返回 Dataframe* 给 SQL 的通用模式：

  1. C++ 函数将 Dataframe* 包装为 sqlite3_value（类型标签 “TABLE”）。
  2. __intrinsic_table_ptr 将其展开为虚拟表，列名为 c0, c1, c2…
  3. __intrinsic_table_ptr_bind 在 WHERE 子句中将列绑定到语义名称（始终返回 true，副作用是绑定）。

命名约定

Section titled “命名约定”
  • 公共模块：无下划线前缀（sched.runnable、slices.with_context）
  • 私有模块：下划线前缀（_runnable_state、_sleep_state）
  • 文件名：snake_case.sql

每个 .sql 文件通过 perfetto_amalgamated_sql_header("stdlib") 打包为单个 C++ 头文件 stdlib.h。文件路径到模块名的映射：sched/runnable.sql → sched.runnable。

深入示例：图扫描

Section titled “深入示例：图扫描”

graphs/scan.sql 实现了图上的函数式”扫描”（前缀和）操作：

  1. __intrinsic_graph_agg(source, dest) —— C++ 聚合，构建压缩图表示。
  2. __intrinsic_row_dataframe_agg(...) —— 构建初始状态行。
  3. __intrinsic_graph_scan(graph, init, step_query, columns) —— 在图上执行扫描。

step_query 是一个 SQL 字符串——C++ 引擎在图的每一步重新执行它。这使得扫描步骤可以是任意 SQL 表达式。

span_join 是一个 SQLite 虚拟表模块（plugins/span_join_operator/），实现两个时间区间表的时序连接：

支持三种变体：span_join（内连接）、span_left_join（左连接）、span_outer_join（外连接）。对于分区表（如 per-CPU），自动处理缺失分区的影子区间。

元编程能力

Section titled “元编程能力”

PerfettoSQL 的宏系统不仅是文本替换——它是一个图灵完备的编译期元编程系统：

可变参数宏：__intrinsic_token_apply! 使得宏可以接受任意数量的参数。

字符串化：__intrinsic_stringify! 将 SQL 表达式转换为字符串字面量，使得宏可以将 SQL 片段作为数据传递给 C++ 函数。

类型标注：宏参数有类型（TableOrSubquery、Expr、ExprList），编译器在替换时做语法检查。

递归展开：宏可以调用其他宏，支持递归展开（有深度限制）。

这些能力使得 PerfettoSQL 的标准库可以提供高度抽象的分析接口，同时保持底层实现的灵活性。

本文小结

Section titled “本文小结”

PerfettoSQL 通过 7 种精确的语法扩展将 SQLite 改造为 trace 分析语言（加上 SqliteSql 透传标准 SQL）。Lemon 语法的 %fallback 设计保持了对标准 SQL 的兼容。栈式执行和 include-once 语义使得模块系统健壮可靠。__intrinsic_table_ptr 桥接模式将 C++ 的 Dataframe 暴露为 SQL 可查询的表。标准库的 23 个模块覆盖了从调度分析到功耗估算的广泛场景。宏系统的元编程能力使得可变参数操作（如多表区间交集）成为可能。
