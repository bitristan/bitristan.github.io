Perfetto （十二）：事件排序器

排序问题

Section titled “排序问题”

Trace 数据的到达顺序与全局时间序不一致。ftrace 事件按 per-CPU 缓冲区到达，不同 CPU 的事件天然交错。某些数据源（如用户空间 TrackEvent）的事件可能来自任意线程。Ring buffer 模式的 trace 可能导致旧事件晚于新事件到达。

Trace Processor 需要将所有事件按全局时间序排列后才能正确解析——因为 slice 的 begin/end 配对、计数器的时序关系、调度事件的因果链都依赖时间序。

架构概览

Section titled “架构概览”

TraceSorter（src/trace_processor/sorter/trace_sorter.h）实现了一个流式多路归并排序。它不等待所有数据到达后一次性排序——它在数据流入时增量排序，支持在 ingestion 中途查询。

核心数据结构

Section titled “核心数据结构”

TimestampedEvent（16 字节）

Section titled “TimestampedEvent（16 字节）”

排序器不存储事件的完整数据——只存储时间戳和一个指向实际数据的引用：

16 字节的事件条目使得排序和归并的 cache 行为极好。

TraceTokenBuffer

Section titled “TraceTokenBuffer”

TraceTokenBuffer 是排序阶段的内存池。它使用 BumpAllocator（64 KB chunk）分配，事件数据（TracePacketData、FtraceData、TrackEventData）连续存储在 chunk 中。

设计目标：最小化峰值内存。排序器需要缓冲所有未提取的事件，这在大型 trace 中可能占用数 GB。BumpAllocator 的零碎片特性使得内存使用可预测。

每 CPU 队列

Section titled “每 CPU 队列”

每个队列是一个 base::CircularQueue<TimestampedEvent>——环形缓冲区，支持高效的尾部追加和头部提取。队列数量 = CPU 数 + 1（非 CPU 事件的通用队列）。

流式提取（增量模式）

Section titled “流式提取（增量模式）”

用于 write_into_file 类型的 trace——数据边流入边可查询。

通过 Flush 和 ReadBuffer 服务事件协调：

  1. NotifyFlushEvent() 递增 flush 计数器。
  2. 当 flushes >= 2 时，NotifyReadBufferEvent() 触发提取。
  3. 提取使用 AllocId 边界确定安全的提取范围——不会提取正在被写入的 token。

全量排序（EOF 模式）

Section titled “全量排序（EOF 模式）”

用于 ring buffer 类型的 trace——所有数据在 EOF 时一次性排序和提取。

ExtractEventsForced() 在 NotifyEndOfFile() 时调用，强制提取所有队列中的所有事件。

TraceTokenBuffer 的内存管理

Section titled “TraceTokenBuffer 的内存管理”

TraceTokenBuffer 使用 BumpAllocator——分配就是推进指针，不需要逐个释放。

58 位地址空间（chunk_index 42 bits + chunk_offset 16 bits）编码在 TimestampedEvent 的高位中，外加 1 bit 的 is_json_event 标记（参与排序决策）。这比直接存储指针（64 位）更紧凑，也使得地址可以被序列化和比较。

分配是线程不安全的——排序器运行在单线程上。这消除了原子操作的开销。

性能特征

Section titled “性能特征”

排序器的性能关键点：

  1. 16 字节事件条目：cache 友好的排序和归并。
  2. Per-CPU 有序假设：99%+ 的事件走快速路径（无排序）。
  3. 局部排序：只排序打破顺序的尾部，不触碰已排序的前缀。
  4. BumpAllocator：零碎片、O(1) 分配、无需逐个释放。
  5. 批量归并：减少队列比较次数。
  6. 单线程：无锁、无原子操作。

在典型的 Android trace（数十万事件）上，排序阶段的耗时通常在数百毫秒级别，远小于 I/O 和解析的时间。

本文小结

Section titled “本文小结”

TraceSorter 是 Trace Processor ingestion 管道的核心。它通过 per-CPU 队列和局部排序利用 ftrace 事件的天然有序性，通过 16 字节的紧凑事件表示和 BumpAllocator 最小化内存开销，通过 Stream/Sink 模式提供类型安全的上下游接口。增量提取模式支持在 ingestion 中途查询，全量排序模式处理 ring buffer 场景。排序器的设计体现了 Perfetto 对性能和内存效率的持续追求。
