Perfetto （八）：ftrace 集成

ftrace 在 Perfetto 中的位置

Section titled “ftrace 在 Perfetto 中的位置”

ftrace 是 Linux 内核内建的追踪框架，几乎所有内核事件——调度、系统调用、中断、电源状态——都通过 ftrace 暴露。Perfetto 的 traced_probes 守护进程中，ftrace 集成是最大也最复杂的子系统。

Tracefs：内核接口层

Section titled “Tracefs：内核接口层”

Perfetto 通过操作 tracefs 虚拟文件系统与 ftrace 交互。类 Tracefs（src/traced/probes/ftrace/tracefs.h）封装了所有文件系统操作。

挂载点发现

Section titled “挂载点发现”

tracefs 有两个常见挂载位置：

CreateGuessingMountPoint() 依次尝试，找到第一个存在的路径。对于命名实例（instance），会在路径后追加 instances/<name>/。

核心操作

Section titled “核心操作”

Tracefs 的操作都是直接读写虚拟文件：

事件控制：

  • EnableEvent(group, name) → 写 "1" 到 events/<group>/<name>/enable
  • DisableAllEvents() → 写 "0" 到 events/enable
  • SetSyscallFilter(filter) → 写过滤表达式到 events/raw_syscalls/sys_enter/filter

缓冲区管理：

  • SetCpuBufferSizeInPages(pages) → 写 buffer_size_kb
  • OpenPipeForCpu(cpu) → 打开 per_cpu/cpu<N>/trace_pipe_raw（O_RDONLY | O_NONBLOCK）
  • ClearTrace() → 截断 trace 文件

追踪控制：

  • SetTracingOn(bool) → 写 tracing_on
  • SetClock(name) → 写 trace_clock（可选值：boot、global、local、mono_raw）
  • SetCurrentTracer(tracer) → 写 current_tracer（如 function_graph）

Kprobe 支持：

  • CreateKprobeEvent(group, name, is_retprobe) → 追加到 kprobe_events 文件
  • RemoveKprobeEvent(group, name) → 追加 "-:group/name" 卸载探针

FtraceController：中央协调器

Section titled “FtraceController：中央协调器”

FtraceController（src/traced/probes/ftrace/ftrace_controller.h/.cc）是 ftrace 子系统的核心。它管理：

  • 主实例（primary_）：使用默认 tracefs 路径，生命周期与 Controller 相同。
  • 次级实例（secondary_instances_）：通过命名 tracefs 路径（如 instances/wifi/）创建，用于隔离不同的追踪会话。次级实例不支持 atrace 和 function_graph。
  • CpuReader：每个实例的每个 CPU 一个。
  • ProtoTranslationTable：ftrace 事件的二进制格式到 protobuf 字段的映射表。
  • FtraceConfigMuxer：合并多个并发数据源的事件配置。

每个实例的状态：

数据源生命周期

Section titled “数据源生命周期”

AddDataSource：

  1. 验证配置（ValidConfig()）。
  2. 获取或创建对应的 FtraceInstanceState。
  3. 调用 FtraceConfigMuxer::SetupConfig() 配置 tracefs：启用事件、设置缓冲区大小、选择时钟、运行 atrace、创建 kprobe。
  4. 调用 data_source->Initialize()。

StartDataSource：

  1. FtraceConfigMuxer::ActivateConfig() 写 tracing_on=1（首个活跃配置时）。
  2. 为每个 CPU 创建 CpuReader，打开 trace_pipe_raw。
  3. 启动周期性 drain 循环（ReadTick）。

RemoveDataSource：

  1. FtraceConfigMuxer::RemoveConfig() 禁用不再需要的事件、清理 kprobe。
  2. 如果没有剩余数据源，重置 current_tracer，释放 CpuReader。

多路复用

Section titled “多路复用”

多个并发的 tracing 会话共享同一个内核 ftrace 实例。FtraceConfigMuxer 维护所有会话请求的事件并集。

当一个新会话请求事件 A 和 B，另一个已有的会话请求事件 B 和 C 时，Muxer 确保 A、B、C 都被启用。当第一个会话结束时，只有 A 被禁用——B 仍被第二个会话需要。

CpuReader 解析出每个事件后，遍历所有活跃的数据源，将事件写入每个关心该事件的数据源的 TraceWriter。这意味着同一个 ftrace 事件可能被写入多个独立的 trace 缓冲区。

Drain 循环

Section titled “Drain 循环”

定时轮询（主要机制）

Section titled “定时轮询（主要机制）”

FtraceController::ReadTick() 是 drain 循环的核心：

  1. 对每个 ftrace 实例调用 ReadPassForInstance()。
  2. 每个 CpuReader 读取最多 kMaxPagesPerCpuPerReadTick = 256 页（1 MB/CPU）。
  3. 如果某个 CPU 读满了 256 页（说明还有更多数据），立即安排下一次 ReadTick。
  4. 否则，延迟调度——默认周期 kDefaultTickPeriodMs = 100 毫秒。

关键常量：

  • kDefaultTickPeriodMs = 100：默认 drain 周期。
  • kMaxPagesPerCpuPerReadTick = 256：每次 tick 每 CPU 最多读取的页数，防止饿死事件循环。
  • 用户可通过 FtraceConfig.drain_period_ms 自定义周期（范围 1-60000 ms）。

基于 Poll 的 Drain（补充机制，v48+ / 内核 v6.9+）

Section titled “基于 Poll 的 Drain（补充机制，v48+ / 内核 v6.9+）”

当配置了 drain_buffer_percent 且内核支持时，Perfetto 使用 poll() 监听 trace_pipe_raw 的 fd。当任何 per-CPU 缓冲区的填充率超过阈值时，内核触发 POLLIN，Perfetto 立即读取。

这比定时轮询更高效——不需要每 100ms 唤醒一次，只在有数据时才读取。默认的 tick 周期也放宽到 1000ms。

需要内核 v6.9+。Perfetto 会检查内核版本号，也识别特定的 Android GKI 内核补丁（android14-6.1.86+、android15-6.6.27+）。

CpuReader：事件解析引擎

Section titled “CpuReader：事件解析引擎”

CpuReader（src/traced/probes/ftrace/cpu_reader.h/.cc）是事件解析的核心。每个 CpuReader 绑定一个 CPU，持有 trace_pipe_raw 的非阻塞 fd。

读取流程

Section titled “读取流程”

ReadCycle() 以 32 页（128 KB）为一批读取，处理完一批再读下一批——保持数据在 L2 cache 中。

ReadAndProcessBatch() 的步骤：

  1. 通过 read(trace_fd, buffer, page_size) 非阻塞读取。
  2. 追赶启发式：如果 page_header.size < page_size / 2（kPageFillThreshold），说明已经追上内核写入端，停止读取（避免读到半写入的页）。
  3. 对每个活跃的数据源调用 ProcessPagesForDataSource()，将解析结果写入该数据源的 TraceWriter。

Ring Buffer 页格式

Section titled “Ring Buffer 页格式”

每个 ftrace ring buffer 页的头部：

每个事件头部 4 字节：低 5 位是类型/长度，高 27 位是时间增量。三种特殊记录：

  • 29（padding）：跳过填充。
  • 30（time_extend）：扩展时间戳的高 32 位。
  • 31（timestamp）：绝对时间戳（内核 4.17+）。

事件分发

Section titled “事件分发”

ParseEvent() 对每个 ftrace 事件进行类型分发：

  1. compact sched：如果是 sched_switch 或 sched_waking 且启用了紧凑编码，走专用路径（后文详述）。
  2. sys_enter / sys_exit：硬编码解析系统调用参数。如果系统调用返回 fd（如 sys_open），记录 (pid, fd) 到 metadata。
  3. kprobe：写入探针名称和类型（instant/begin/end）。
  4. 通用事件：如果是编译时未知的事件，用 GenericFtraceEvent 包装（事件名 + 字段 oneof），或使用自描述 proto 描述符。
  5. 已知事件：遍历预解析的字段列表，通过 TranslationStrategy 将 ftrace 二进制类型映射到 proto 字段。

TranslationStrategy 枚举定义了映射方式：kUint32ToUint64、kInt32ToInt32、kFixedCStringToString、kDataLocToString、kInode32ToUint64、kFtraceSymAddr32ToUint64 等。

Compact Sched：热路径优化

Section titled “Compact Sched：热路径优化”

sched_switch 和 sched_waking 是体积最大的 ftrace 事件——在繁忙系统上每秒数万个。逐事件序列化为 protobuf 的开销不可忽视。

Compact sched 使用结构体数组（Structure of Arrays）替代数组结构体（Array of Structures）：

优化手段：

  • 时间戳 delta 编码：第一个绝对值，后续存储与前一个的差值。
  • Comm 字符串去重：每个 bundle 内维护一个 CommInterner，线性扫描最多 kMaxElements = 4096 个条目。大多数系统上的 comm 字符串不超过几十个。
  • Packed varint 数组：pid、priority、state 打包为连续的 varint 流。

阈值：当 interner 积累超过 kCompactSchedInternerThreshold = 64 个唯一字符串时，强制开启新 bundle 以刷新 interning 状态。

格式验证在初始化时进行（ValidateFormatForCompactSched）：检查内核的字段偏移和类型是否匹配预期布局（如 next_comm 必须是固定的 16 字节 C 字符串）。

FtraceConfig：配置选项

Section titled “FtraceConfig：配置选项”

FtraceConfig（protos/perfetto/config/ftrace/ftrace_config.proto）的核心选项：

字段说明
ftrace_events要记录的事件。格式："group/name" 或 "group/*"
atrace_categoriesAndroid atrace 类别（如 "gfx"、"sched"）
atrace_apps用户空间追踪的应用包名
buffer_size_kbper-CPU 内核 ring buffer 大小。默认：低内存 2 MB，≥7 GB RAM 8 MB
drain_period_ms读取周期。默认 100 ms
compact_sched紧凑编码配置。默认启用
symbolize_ksyms启用 /proc/kallsyms 符号解析
kprobe_events动态 kprobe/kretprobe 定义
preserve_ftrace_buffer启动时不清空内核缓冲区（用于 boot trace）
instance_name使用命名 tracefs 实例
tids_to_trace按 TID 过滤事件（v52+，需要 exclusive session）
function_filtersfunction_graph 跟踪的内核函数

atrace 集成

Section titled “atrace 集成”

atrace 是 Android 的用户空间追踪标记系统。当配置了 atrace_categories 或 atrace_apps 时，Perfetto 调用 /system/bin/atrace --async_start 来启用对应的 tracepoint。这比手动管理每个事件更方便——一个 atrace 类别可能对应几十个内核事件。

atrace_categories_prefer_sdk 字段是一个过渡机制：对于同时支持 atrace 和 Perfetto SDK 的类别，优先使用 SDK（更高效的 ProtoZero 写入路径）。

Kprobe 动态探针

Section titled “Kprobe 动态探针”

Perfetto 支持在运行时动态创建内核探针，无需重新编译内核。

配置方式：

设置流程（FtraceConfigMuxer::SetupConfig）：

  1. 验证探针名称（只允许字母数字和下划线）。
  2. 写入 kprobe_events 文件：p:perfetto_kprobes/do_sys_open do_sys_open（入口探针）或 r1024:perfetto_kretprobes/do_sys_open do_sys_open（返回探针，1024 是最大并发数）。
  3. 在 ProtoTranslationTable 中注册事件。
  4. 启用事件。

KPROBE_TYPE_BOTH 同时创建入口和返回探针，产生 BEGIN 和 END 类型的事件——可以用来测量函数执行时间。

清理时，写入 "-:group/name" 卸载探针。ReadKprobeStats() 读取 kprobe_profile 获取命中/未命中统计。

时钟同步

Section titled “时钟同步”

ftrace 使用内核时钟记录事件时间戳，但这个时钟不一定与 Perfetto 其他数据源使用的时钟相同。

时钟选择

Section titled “时钟选择”

Perfetto 按优先级尝试：boot > global > local。如果配置了 use_monotonic_raw_clock = true，使用 mono_raw。

boot 时钟（CLOCK_BOOTTIME）是首选——它与 Perfetto 的其他时间戳使用相同的时钟源，无需额外对齐。

时钟快照

Section titled “时钟快照”

当不使用 boot 时钟时，Perfetto 在每次 drain tick 开始时拍摄时钟快照：

ReadFtraceNowTs() 从 /sys/kernel/tracing/per_cpu/cpu0/stats 中读取 now_ts: 字段。

快照写入 FtraceEventBundle 的三个字段：

  • ftrace_clock：使用的时钟类型。
  • ftrace_timestamp：ftrace 时钟的当前值（读取时刻）。
  • boot_timestamp：同一时刻的 CLOCK_BOOTTIME 值。

Trace Processor 用这些快照对做最优拟合时钟对齐——将 ftrace 时间戳转换为 boot 时间戳。

安全与隐私

Section titled “安全与隐私”

内核符号脱敏

Section titled “内核符号脱敏”

当启用 symbolize_ksyms 时，Perfetto 读取 /proc/kallsyms 获取内核符号地址。但这些地址包含 KASLR（内核地址空间布局随机化）信息，可能泄露内核内存布局。

Perfetto 的处理：符号地址被替换为插入顺序的索引。原始地址不会出现在 trace 中。Trace Processor 只看到 “函数 #42”，而非 “函数 0xffffffff81234567”。

Exclusive Session 特性

Section titled “Exclusive Session 特性”

tids_to_trace、tracefs_options、tracing_cpumask 等 v52+ 特性需要 exclusive session——不允许并发的 ftrace 数据源。这是因为这些特性操作的是全局 tracefs 状态（如 set_event_pid），无法安全地在多个会话间共享。

本文小结

Section titled “本文小结”

Perfetto 的 ftrace 集成是一个完整的内核事件采集管道。从 tracefs 文件系统的操作、到 ring buffer 的非阻塞读取、到事件的二进制解析和 protobuf 编码、到多路复用的会话管理——每个环节都针对性能做了优化。Compact sched 编码对热路径事件的压缩尤为关键。时钟同步和内核符号脱敏则保证了 trace 数据的可用性和安全性。
