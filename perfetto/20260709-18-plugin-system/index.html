Perfetto （十八）：插件系统

插件的定位

Section titled “插件的定位”

Trace Processor 的功能不是单体的——它通过插件系统模块化扩展。57 个插件各自负责一个特定的分析域：从调度追踪到堆图分析到符号化。插件在编译时注册，在 Trace Processor 启动时按依赖拓扑排序加载。

插件的类型

Section titled “插件的类型”

ProtoImporterModule

Section titled “ProtoImporterModule”

处理特定类型的 TracePacket。当 Trace Sorter 提取一个 TracePacket 时，ProtoTraceParserImpl 按 packet 中的数据类型分发给对应的 ProtoImporterModule：

57 个插件中，大多数注册为 ProtoImporterModule：

插件处理的 packet 类型
schedFTRACE_EVENT (sched_switch, sched_waking)
sliceTRACK_EVENT (slice begin/end)
counterTRACK_EVENT (counter)
process_treePROCESS_TREE
heap_graphHEAP_GRAPH
powerBATTERY, POWER_RAILS
android_logANDROID_LOG
ftrace_statsFTRACE_STATS
clock_snapshotCLOCK_SNAPSHOT
sys_statsSYS_STATS
triggerTRIGGER
……

StaticTableFunction

Section titled “StaticTableFunction”

注册表值函数（table-valued function），如 ancestor_slice(id) 和 descendant_slice(id)：

ancestor_slice(42) 在 SQL 中表现为一个虚拟表，返回 slice #42 的所有祖先。Cursor::Next() 内部遍历 parent_id 链。

sqlite::Module

Section titled “sqlite::Module”

注册 SQLite 虚拟表模块，如 span_join：

CREATE VIRTUAL TABLE sp USING span_join(t1, t2) 创建一个时序连接虚拟表。

数据库注册

Section titled “数据库注册”

插件可以注册 Dataframe 表——这些表在 EOF 后 finalize，构建索引，然后通过 DataframeModule 暴露为 SQL 可查询的表。

插件的生命周期

Section titled “插件的生命周期”

注册

Section titled “注册”

插件在静态初始化时通过 GetPluginSet() 注册。每个插件通过模板参数声明自己的依赖：

Plugin<Self, Deps...> 模板的作用：

  1. 编译时：强制 #include 依赖的头文件 → 强制 GN 依赖。
  2. 链接时：如果依赖的 .cc 未编译，GN 依赖缺失 → 构建失败。
  3. 运行时：GetPluginSet() 拓扑排序验证所有依赖已注册。

运行时通过 dependency<T>() 访问依赖插件实例——索引在编译时从参数包位置解析。

初始化

Section titled “初始化”

TraceProcessorImpl 构造函数遍历排序后的插件列表，调用每个插件的注册方法。注册是分阶段的：

  1. Importer 注册：RegisterImporters() + RegisterProtoImporterModules() —— 使插件能处理特定的 TracePacket 类型。
  2. SQL 函数注册：RegisterFunctions() + RegisterAggregateFunctions() + RegisterWindowFunctions() —— 注册 C++ 函数为 SQLite 函数。
  3. 虚拟表注册：RegisterSqliteModules() + RegisterStaticTableFunctions() —— 注册 SQLite 虚拟表模块和表值函数。
  4. Dataframe 注册：RegisterDataframes() —— 注册列式表。

运行时

Section titled “运行时”

在 trace 解析期间，插件的 ParsePacket() 被调用——从 TracePacket 中提取数据，写入 TraceStorage 的表中。

EOF

Section titled “EOF”

NotifyEndOfFile() 触发所有插件的 finalize——补充延迟计算的字段、构建索引、释放临时状态。

TraceProcessorContext：共享状态

Section titled “TraceProcessorContext：共享状态”

所有插件通过 TraceProcessorContext 访问共享状态：

上下文有精密的分叉模型：

  • 全局状态：跨所有 trace/机器共享（TraceStorage、TraceSorter）。
  • Per-trace 状态：每个文件独立（content_analyzer）。
  • Per-machine 状态：每个虚拟机独立（ProcessTracker、CpuTracker）。
  • Per-trace-and-machine 状态：（ClockTracker、SliceTracker）。

归档中的多个文件通过 ForkContextForTrace() 分叉上下文。

关键插件示例

Section titled “关键插件示例”

ancestor 插件

Section titled “ancestor 插件”

实现 ancestor_slice() 和 ancestor_stack_profile_callsite() 表值函数。

Ancestor 类遍历 parent_id 链，每次 Next() 推进到下一层祖先。它使用 SliceTable 的类型化索引实现 O(1) 的行访问。

span_join_operator 插件

Section titled “span_join_operator 插件”

实现时间区间连接——两个表的时间区间按重叠关系连接。

状态机设计（每个表的状态）：

  • kReal：来自原始表的真实区间。
  • kPresentPartitionShadow：当前分区的影子区间（填充间隙）。
  • kMissingPartitionShadow：缺失分区的影子区间。
  • kEof：该表已耗尽。

critical_path 插件

Section titled “critical_path 插件”

实现 __intrinsic_critical_path_walk——关键路径图遍历的核心 C++ 函数。它接收 wakeup 图的压缩表示和根节点数组，返回阻塞链序列。

graph_scan 插件

Section titled “graph_scan 插件”

实现 __intrinsic_graph_scan 和 __intrinsic_graph_aggregating_scan——图上的前缀和扫描。这是一个通用的图算法框架，被支配树、火焰图累积等分析使用。

table_pointer_module 插件

Section titled “table_pointer_module 插件”

实现 __intrinsic_table_ptr / __intrinsic_table_ptr_bind——将 C++ 的 Dataframe* 暴露为 SQL 虚拟表的通用桥接机制。

插件间协作

Section titled “插件间协作”

插件不是孤立的——它们通过共享的 TraceStorage 和 TraceProcessorContext 协作：

插件的依赖声明确保了执行顺序——但运行时的实际依赖是通过表的引用实现的。

插件 vs 标准库

Section titled “插件 vs 标准库”

插件和标准库（stdlib SQL 模块）的关系：

维度插件标准库
语言C++SQL
注册时机编译时运行时（INCLUDE MODULE）
性能适合 CPU 密集型操作适合声明式查询
接口ProtoImporterModule, StaticTableFunction, sqlite::ModulePerfetto TABLE/FUNCTION/MACRO
典型用途数据导入、图算法、区间交集查询、聚合、关联分析

插件提供计算原语，标准库提供分析接口。例如：__intrinsic_critical_path_walk 是插件（C++），_critical_path_by_roots 是标准库（SQL 宏，调用 C++ 函数）。

本文小结

Section titled “本文小结”

Trace Processor 的插件系统是其可扩展性的基础。57 个插件通过编译时注册和拓扑排序加载，各自负责一个特定的分析域。插件可以注册 ProtoImporterModule（数据导入）、StaticTableFunction（表值函数）、sqlite::Module（虚拟表）和 C++ 函数（计算原语）。TraceProcessorContext 提供共享状态，分叉模型支持多文件归档。插件与标准库形成互补关系——插件提供 C++ 的计算原语，标准库提供 SQL 的分析接口。

本系列 18 篇文章到此结束。从三方架构模型到共享内存缓冲区、从 ProtoZero 序列化到 IPC 通信、从 ftrace 集成到 Tracing SDK、从 Trace Processor 的 ingestion 管道到 PerfettoSQL 标准库——我们完整地走过了 Perfetto 从内核事件采集到 SQL 查询结果的全部数据路径。
