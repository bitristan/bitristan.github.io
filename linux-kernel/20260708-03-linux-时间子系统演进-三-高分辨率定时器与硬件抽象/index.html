Linux 时间子系统演进（三）：高分辨率定时器与硬件抽象

聚焦版本：Linux 2.6.x（主线 2.6.16 - 2.6.30 前后）

1. 为什么需要变革

Section titled “1. 为什么需要变革”

进入 21 世纪后，Linux 面临的使用场景发生了巨大变化：

  • 实时应用（工业控制、音视频处理）要求微秒甚至纳秒级定时精度。
  • 笔记本电脑和嵌入式设备对空闲功耗极度敏感，固定 100Hz/250Hz tick 成为耗电元凶。
  • 多核处理器兴起，每个 CPU 都维护自己的 tick 和时钟源，代码重复且难以扩展。
  • 硬件多样化：x86 上同时存在 TSC、HPET、ACPI PM Timer，ARM 有 arch timer，PowerPC 有 decrementer。每个架构都写一套时间代码不可持续。

Linux 2.6 系列用三个相互关联的子系统回应了这些挑战：

子系统合入主线核心贡献者解决的问题
hrtimer2.6.16Thomas Gleixner, Ingo Molnar纳秒级定时器，与 jiffies 解耦
clocksource / GTOD2.6.18John Stultz 等统一抽象时钟源，架构无关 timekeeping
clockevent2.6.18-2.6.21Thomas Gleixner, Ingo Molnar统一抽象时钟事件设备，支持 oneshot 模式

2. hrtimer：纳秒级定时器框架

Section titled “2. hrtimer：纳秒级定时器框架”

2.1 与 timer_list 的本质区别

Section titled “2.1 与 timer_list 的本质区别”

timer_list 以 jiffies 为单位，精度受 HZ 限制；hrtimer 以 ktime_t（纳秒）为单位，精度只受硬件限制。

2.2 核心数据结构

Section titled “2.2 核心数据结构”

每个 CPU 维护一组 hrtimer base，每个 base 对应一种 clockid（早期主要是 MONOTONIC 和 REALTIME，后续逐步加入 BOOTTIME、TAI 等）。每个 base 内部是一棵按到期时间排序的红黑树。

struct timerqueue_node 内嵌了 struct rb_node node 和 ktime_t expires。红黑树保证最先到期的定时器始终在最左侧，查找下一个到期时间只需 O(1)。

2.3 使用方式

Section titled “2.3 使用方式”

到期时，如果系统已启用高分辨率模式，clockevent 设备会在精确时刻触发中断；如果硬件只支持周期 tick，hrtimer 会在最近的 tick 边界软中断中处理。

2.4 红黑树保证 O(log n)

Section titled “2.4 红黑树保证 O(log n)”

插入、删除、重新武装都是 O(log n)，而查找下一个到期事件是 O(1)。

3. clocksource：统一时钟源抽象

Section titled “3. clocksource：统一时钟源抽象”

3.1 设计思想

Section titled “3.1 设计思想”

在 2.6 之前，读取时间的代码分散在各个架构目录中。GTOD（Generic Time of Day）框架把”读时间”抽象成统一的 struct clocksource：

  • read()：读取硬件计数器的当前 cycle 值。
  • mask：计数器位宽掩码，用于处理回绕。
  • mult/shift：把 cycle 转换为纳秒的定点数因子。
  • rating：质量评分，越高越优先使用。

3.2 cycle 到 ns 的转换

Section titled “3.2 cycle 到 ns 的转换”

为了避免浮点除法，clocksource 使用定点乘法：

mult 和 shift 在注册时通过 clocks_calc_mult_shift() 计算，保证在 maxsec 范围内不溢出且精度最高。这个思想到今天仍是 timekeeping 的核心。

3.3 多个 clocksource 的自动选择

Section titled “3.3 多个 clocksource 的自动选择”

clocksource_watchdog 会周期性地验证当前 clocksource 是否单调、是否与参考时钟一致。一旦 TSC 被判定为不稳定（例如变频、SMI 干扰），系统会自动切换到 HPET 或 ACPI PM timer。

4. clockevent：统一时钟事件抽象

Section titled “4. clockevent：统一时钟事件抽象”

4.1 clocksource 与 clockevent 的分工

Section titled “4.1 clocksource 与 clockevent 的分工”

这是 2.6 时间子系统最关键的概念划分：

抽象作用例子
clocksource读取当前时间（被动、只读）TSC、HPET、ACPI PM Timer
clockevent在未来某个时间点触发中断（主动、可编程）PIT、Local APIC Timer、HPET

一个硬件可以同时具备两种能力（例如 HPET 既可读也可触发中断），但框架层面把它们分开管理。

4.2 核心数据结构

Section titled “4.2 核心数据结构”
  • set_state_periodic：设置为周期模式，驱动传统 tick。
  • set_state_oneshot：设置为单次触发模式，这是高分辨率定时器和 tickless 的基础。
  • set_next_event(evt)：编程下一次中断在多少纳秒后发生。

4.3 事件处理流程

Section titled “4.3 事件处理流程”

当 clockevent 触发中断时，会调用 event_handler。根据系统状态，这个 handler 可能是：

  • tick_handle_periodic：传统周期 tick。
  • hrtimer_interrupt：高分辨率定时器到期。
  • tick_nohz_handler：动态 tick 模式下的 tick 处理。

5. 三者如何协作

Section titled “5. 三者如何协作”

把 hrtimer、clocksource、clockevent 放在一起，就构成了 2.6 时间子系统的新骨架：

  1. clocksource 提供单调递增的 cycle 计数。
  2. timekeeping 把 cycle 转换成 ktime_t（纳秒），维护 wall time、monotonic time、boot time 等。
  3. 内核或用户通过 hrtimer_start() 设定一个未来时间点。
  4. hrtimer 把红黑树最左侧的到期时间交给 clockevent。
  5. clockevent 用单次触发模式在精确时刻产生中断。
  6. 中断中调用 hrtimer_interrupt()，执行到期回调。

6. 高分辨率模式如何启用

Section titled “6. 高分辨率模式如何启用”

CONFIG_HIGH_RES_TIMERS 是开关。启用后，系统启动时会检查所有注册的 clockevent 设备是否支持 CLOCK_EVT_FEAT_ONESHOT。如果支持，tick 设备会从周期模式切换到单次触发模式，hrtimer 就能真正脱离 jiffies。

7. 优点总结

Section titled “7. 优点总结”
  1. 纳秒级精度：定时器不再受 HZ 限制，nanosleep()、POSIX timer、调度器 slice 都能达到微秒/纳秒精度。
  2. 架构无关：GTOD 把 90% 的时间代码抽到 kernel/time/，架构只需实现 clocksource_read() 和 clockevent 回调。
  3. 硬件可插拔：新硬件以驱动形式注册 clocksource/clockevent，无需修改核心。
  4. 自动降级：TSC 不稳定时自动切换到 HPET/ACPI，保证系统时间正确。
  5. 为 tickless 奠基：单次触发 clockevent 是后续 NO_HZ 的前提条件。

8. 局限与未解决的问题

Section titled “8. 局限与未解决的问题”

尽管 2.6 的时间子系统已经现代化，但仍有明显短板：

8.1 tick 仍然是周期性的

Section titled “8.1 tick 仍然是周期性的”

hrtimer 虽然精度高，但调度器、进程记账、jiffies 更新依然依赖周期 tick。CPU 空闲时，tick 依然每秒触发 100/250/1000 次。

8.2 多核扩展问题

Section titled “8.2 多核扩展问题”

每个 CPU 一个 tick，所有 CPU 同时空闲时仍各自被周期唤醒，功耗改善有限。

8.3 实时抖动

Section titled “8.3 实时抖动”

周期 tick 会周期性地打断正在运行的任务，对实时和 HPC 应用仍是噪声源。

8.4 sched_clock 尚未统一

Section titled “8.4 sched_clock 尚未统一”

2.6 早期 sched_clock() 仍由架构各自实现，有的用 jiffies，有的用 TSC，有的用折中方案，调度器在不同架构上行为不一致。

9. 向 tickless 时代过渡

Section titled “9. 向 tickless 时代过渡”

hrtimer + clocksource + clockevent 已经解决了”定时准不准”和”硬件如何抽象”两个问题。剩下的核心问题是：

如果 CPU 没有任务要做，为什么还要周期性地醒来？

答案是：不应该。只要能把周期 tick 改为按需触发，就能在空闲时关掉 tick。这正是下一时代 NO_HZ / dynticks 的目标。而 2.6 引入的 oneshot clockevent 和红黑树 hrtimer，正好为 tickless 提供了全部基础设施。

10. 小结

Section titled “10. 小结”

Linux 2.6 是现代时间子系统的奠基期。hrtimer 用红黑树实现了纳秒级定时；clocksource 把读取时间的硬件统一抽象；clockevent 把触发中断的硬件统一抽象。三者配合，使时间子系统第一次具备了精度高、架构无关、硬件可扩展的特性。但周期 tick 依然存在，空闲功耗和实时 jitter 仍是未竟之事，这为 2.6.21 之后的 tickless 革命埋下了伏笔。
